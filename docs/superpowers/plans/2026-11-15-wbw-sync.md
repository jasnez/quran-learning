# Word-by-word sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "Rijec po rijec" highlights the recited word (reader + learn mode) on per-ayah everyayah audio, with tajwid colors and no word meanings; WBW no longer switches to the chapter MP3, so ayah boundaries/repeat work in the background.

**Architecture:** Pure helpers turn the ayah's `tajwidSegments` into words and the verse's chapter-audio segments into an ayah-relative timeline (`startMs - timestampFrom`, validated per verse). One `AyahWordByWord` component renders them for both screens. The chapter-MP3 playback path (store fields, rAF boundary logic, chapter renderer) is deleted.

**Tech Stack:** Next.js 16 static export, React, Zustand, Vitest + Testing Library (jsdom).

**Spec:** `docs/superpowers/specs/2026-11-15-wbw-sync-design.md`

## Global Constraints

- No word meanings and no per-word transliteration in the UI. No English text from `translationShort`.
- No new dependencies; data stays static (`output: "export"`, no API routes).
- Tajwid colors per segment inside words, same classes as `TajwidTextRenderer` (`tajwidRuleClasses`), only when `showTajwidColors` is on.
- Do not add per-frame work (P1-9): no new store subscriptions at 60 fps; word spans memoized.
- UI copy in Bosnian; code, comments, commits in English.
- Commit only when the user asks; stage files by name; one logical change per commit.
- Gates: `npx vitest run`; `npm run lint`; `npx tsc --noEmit` (exactly 56 pre-existing errors, all in `__tests__`); `npm run build`.

## Review Focus

1. Clicking a word in an ayah that is not playing: playback must start at that word (pending seek), not at 0. -> Task 5 test.
2. Toggling WBW while an ayah plays must not reload or restart audio. -> Task 4 test.
3. Chapter-audio JSON fetch fails (offline): Bosnian message, normal tajwid text, no crash. -> Task 5 test.
4. Repeated words (2:14) and time in gaps/before first word/after last word: highlight goes back on repeats, never blinks off mid-verse. -> Task 1 tests.
5. Highlight readability with tajwid colors in light/dark/sepia themes. -> Task 7 manual browser check.

### Task 1: Ayah-relative word timeline (pure)

**Files:**
- Create: `src/lib/quran/wbwTiming.ts`
- Test: `src/lib/quran/__tests__/wbwTiming.test.ts`

**Interfaces:**
- Produces:
  - `export type AyahWordTiming = { wordIndex: number; startMs: number; endMs: number }` (`wordIndex` 0-based = `wordPosition - 1`; times ayah-relative ms)
  - `export function buildAyahWordTimeline(verse: VerseTimestamp, wordCount: number): AyahWordTiming[] | null` (null = highlight disabled for this verse)
  - `export function findActiveWordIndex(timeline: AyahWordTiming[], timeMs: number): number` (-1 before the first word starts)

Rules (from spec): times are `startMs - timestampFrom` / `endMs - timestampFrom`, no scaling. Return null when: no segments; any segment starts before the previous one; last segment `endMs < timestampTo - 1500` or `> timestampTo + 300`; first segment starts before `timestampFrom - 500` AND the second segment (if any) starts before `timestampFrom - 200`. Otherwise clamp negative starts to 0. Drop segments with `wordPosition < 1` or `> wordCount`. Active word: the last entry with `startMs <= timeMs` (so gaps keep the previous word, repeats re-activate earlier words, and after the last word it stays on the last word).

### Task 2: Split tajwid segments into words + data check

**Files:**
- Create: `src/lib/quran/splitTajwidIntoWords.ts`
- Test: `src/lib/quran/__tests__/splitTajwidIntoWords.test.ts`, `src/lib/quran/__tests__/wbwData.test.ts`

**Interfaces:**
- Consumes: `buildAyahWordTimeline` (Task 1) in the data test only.
- Produces: `export function splitTajwidIntoWords(segments: TajwidSegment[], verseKey: string): TajwidSegment[][]` (one array of colored pieces per word, waqf signs U+06D6-U+06ED removed from the text, whitespace removed, empty pieces dropped).

Algorithm: walk segment text code point by code point; skip waqf signs; whitespace closes the current word (if non-empty); a segment split by a space contributes a piece to each word, each with the segment's `rule`. Then apply `WORD_MERGES: Record<string, number> = { "2:181": 2, "8:6": 3, "13:37": 7, "37:130": 2 }`: merge word i with word i+1, inserting a `{ text: " ", rule: "normal" }` piece between them (Quran.com counts these as one word).
